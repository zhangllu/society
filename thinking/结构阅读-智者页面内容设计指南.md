# 结构阅读：智者页面内容设计指南

> 适用对象：为思想家、学者、作家、艺术家或其他“智者”制作学习页面、导读卡、知识底稿的作者与 AI。
>
> 核心任务：先重建一位智者如何认识和解释世界，再决定如何呈现；不可先做概念清单、人物关系图或页面信息架构。

---

## 1. 这份指南解决什么问题

智者页面最容易滑向两种形式：

1. **人物百科**：生平、名言、著作、概念、影响者依次罗列；
2. **概念工具箱**：把思想压缩成几个可立即应用的名词。

两者都可能有用，却无法帮助读者理解：这位作者为什么必须这样思考、这些概念如何长出来、读者该把注意力放在哪里。

结构阅读的目标，是让读者能够沿着智者的知识生成过程阅读：

```text
问题／困境
→ 既有解释的不足
→ 对象、材料与证据
→ 作者的处理动作
→ 理论对话与历史位置
→ 概念、判断和文本结构
→ 读者可以继续追踪的阅读线索
```

---

## 2. 对“结构阅读”的工作定义

结构阅读不是：

- 给作者贴上“田野调查”“思想实验”等分类名；
- 把一本书的目录改写成思维导图；
- 提炼几个概念后直接迁移到日常生活；
- 依靠人物影响链代替论证分析。

结构阅读是：

> 通过作者的文本、材料、概念、论敌、证据标准和行文组织，重建其认识世界与提出判断的方式。

《聪明的阅读者》所说的冰山模型可作为观察框架：

```text
文本格式与写作规约      章法、体裁、引文、叙述与论证安排
研究方法论              材料是什么、何种证据有效、如何从材料到判断
认知方式                作者偏好的问题、观察、比较、抽象、解释与改造动作
```

三层不可颠倒。认知方式是最底层的提炼，不是最先写在页面上的标签。

---

## 3. 必须区分的四个层次

新手和 AI 最容易把不同层次的东西混为一谈。制作前必须分开：

| 层次 | 要问的问题 | 不能误作 |
|---|---|---|
| 大问题 | 作者试图解决的人类、社会或创作难题是什么？ | 一个学科名称 |
| 概念 | 作者创造或改写了什么概念来推进问题？ | 孤立的知识点 |
| 认知方式 | 作者如何把概念、材料、推理动作串成解决问题的模式？ | 九种认知方式中的一个标签 |
| 学科／传统 | 这套工作在何种共同体、体裁与争论中发生？ | 作者思想的全部解释 |

可用下面的顺序自检：

```text
大问题为何存在
→ 概念为何被发明
→ 概念怎样被串接成解释
→ 学科与传统如何提供资源、限制和对手
```

---

## 4. 工作前：建立资料与证据边界

### 4.1 先确定页面究竟在读谁

一个页面可能同时包含三种对象：

1. **原作者／智者本人**：原著中的命题、概念、材料、论证；
2. **导读作者**：二手著作如何选择、组织、评价这位智者；
3. **后世接受者**：后人如何继承、批评、改写或误读这位智者。

三者绝不可混写。

例如，一本社会学史教材以某个主线介绍韦伯，这首先是教材作者的解释结构；只有回到韦伯原著，才能判断哪些说法能直接归于韦伯。

### 4.2 资料分层

| 资料层 | 用途 | 写作规则 |
|---|---|---|
| 原著／原始作品 | 核实概念、判断、论证和文本形式 | 关键命题优先以此为准，记录版本与位置 |
| 高质量二手导读 | 重建全局、定位争议、发现章节线索 | 明确写成“某导读的解释”，不可伪装成原作者原话 |
| 同时代对话文本 | 确认作者真正回应的对象 | 只在能说明具体分歧时使用 |
| 后世研究与批评 | 展示接受史、盲区与争议 | 区分直接继承、相似问题和批评性重读 |
| 通俗介绍或网页 | 发现线索 | 不作为关键判断的唯一依据 |

### 4.3 关键命题的证据卡

每一个准备写入页面的重要判断，先做一张内部证据卡：

```markdown
## 命题
[一句准备写入页面的判断]

## 证据身份
- [ ] 原著命题
- [ ] 二手解释
- [ ] 后世争论

## 来源
[作者、书名、版本、章节或页码]

## 原文／准确转述
[简短摘录或严格转述]

## 它在整体结构中的作用
[它在回答什么问题？连接了哪一步？]

## 限制
[是否存在争议、例外或尚待核实处？]
```

## 5. 核心工作流：先做结构底稿，后做页面

### 第一步：找出真正的问题，而非主题

不要写“作者研究权力”“作者讨论爱情”“作者是社会学家”。这些只是主题或领域。

要写成有张力的问题：

- 什么现象使作者感到已有解释不够？
- 作者试图解释怎样的矛盾、反常、变化或经验？
- 这个问题为何在他的时代成立？

**合格标准**：问题必须能引出“为什么需要这些概念和论证”，而不是只能引出一个知识分类。

### 第二步：重建作者面对的材料与对象

问清楚作者到底在“看”什么：

- 亲身经验、实验、田野、档案、历史事件、法律文本、宗教作品、小说、图像，还是既有理论？
- 作者处理的是个人、群体、制度、符号、文本、历史过程，还是自然对象？
- 哪些材料被视为证据，哪些只作为例子或修辞？

**注意**：使用历史文献不等于“文献田野”；使用抽象概念也不自动等于“思想实验”。先描述实际工作，再考虑提炼。

### 第三步：找出作者的知识动作

这是结构阅读的核心。不要先填“方法名称”，要用动词写出作者反复在做什么：

- 区分什么与什么？
- 从何种混杂现实中抽出什么形式？
- 比较哪些案例、时代、文本或群体？
- 排除或反驳了什么解释？
- 如何把局部材料推到较一般的判断？
- 又如何用一般判断返回具体案例？

示例句式：

> 作者先将现实中混杂的 X 与 Y 拆开，以便看清它们各自的动力；随后再考察二者在具体情境中怎样重新结合。

这类句子比“作者使用理想型”“作者采用田野调查”更接近可阅读、可验证的结构。

### 第四步：重建理论对话，而非师承名单

理论关系只在它改变作者的问题、材料、概念或结论时才应进入页面。

每条关系都应回答：

1. 对方提出了什么重要答案？
2. 本作者接住了什么？
3. 他认为哪里不够，因而作了什么改变？
4. 这种分歧如何进入本作者的概念或论证？

禁止将“读过／认识／同代／后来受影响”自动写成“师承”。

### 第五步：将概念还原为“问题的回答”

每个核心概念都应按照以下模板处理：

```markdown
### [概念]

**它要处理的问题**：

**它反对或补足的解释**：

**它如何从材料与论证中长出**：

**与其他概念如何连接**：

**边界／争议／常见误读**：
```

若一个概念无法回答这些问题，就暂不进入核心页面。

### 第六步：解释文本为何这样组织

不要将书的章节顺序当作自然的事实。要问：

- 作者为什么先定义、再比较、再提出结论？
- 某概念为何在另一个概念之后出现？
- 哪些章节是论证主干，哪些是例证、延展、反驳或格式性安排？
- 二手导读为何这样重组原作者？

这一步会把“目录”转化为真正的结构阅读。

### 第七步：最后才提炼认知方式

完成前六步后，可以用一句话总结作者反复出现的知识动作：

> 面对 [问题]，作者倾向于借由 [材料]，通过 [关键动作]，在与 [对话对象／传统] 的张力中，形成 [判断]。

如需参照“九种认知方式”，只能将其作为补充说明，并注明该作者通常同时综合多种方式。不得用类别替代前述具体分析。

## 6. 其他阅读方法的位置：补充，不取代结构阅读

文本细读、抽样阅读、主题阅读、卡片写作都重要，但它们不是页面栏目，也不应盖过结构阅读。

| 方法 | 在结构阅读中的作用 | 不应变成 |
|---|---|---|
| 文本细读 | 核对术语边界、主题句、论证转折、反例和引用 | 独立的“细读实验室”装饰模块 |
| 抽样阅读 | 快速找到最能暴露整体结构的章节和段落 | 让用户填写阅读测验的流程 |
| 主题阅读 | 看清对话对象、竞争解释与接受史 | 空泛的推荐书单或人物墙 |
| 卡片写作 | 保存“问题—材料—动作—概念—对话”的结构成果 | 强制用户完成的卡片任务 |
| 图示 | 呈现难以线性说明的关系 | 用关系图替代论证 |

原则：**方法应在读者阅读内容时被自然调用，而不必在页面上以方法名出现。**

---

## 7. 从结构底稿到页面：允许转换，不允许压扁

页面不是研究底稿的逐段搬运。可以从读者熟悉的情境或困惑进入，但必须返回作者的真实问题和论证。

### 推荐的内容顺序

```text
一个需要解释的现象或困境
→ 作者为何觉得通常解释不够
→ 作者怎样观察、比较或建构问题
→ 概念如何依次回应这个问题
→ 关键理论对话
→ 读者带着什么新问题回到原著或现实
```

### 页面内容的最低要求

- 至少有一个被清晰提出的核心问题；
- 至少呈现一次“已有解释 → 作者修正 → 新概念／新判断”的过程；
- 每个核心概念都能回到一个问题和论证位置；
- 至少区分原著命题、二手解释和后世争论；
- 提供回到原著的具体入口，而非只给作品名单；
- 不以人物生平、金句、影响者清单代替结构。

---

## 8. 常见失败模式与修正

| 失败模式 | 为什么失败 | 修正方式 |
|---|---|---|
| 先给认知方式分类 | 用结果替代分析，常造成误判 | 先写材料、动作、对话；分类只在最后提炼 |
| 概念并列成工具箱 | 读者记住名词，却不知道概念为何出现 | 为每个概念补“问题—对手—生成—连接—边界” |
| 用日常例子快速解释一切 | 容易把作者复杂理论降成万能职场诊断 | 先完成原论证，再有限迁移，并保留不适用处 |
| 人物关系图过大 | 关系看似丰富，实际没有理论信息 | 只保留改变概念或论证的关系，并写清分歧 |
| 把二手导读当成原著 | 页面会复制导读作者的偏见或删节 | 标注解释来源，并为关键命题回到原著 |
| 将“学科”当作底层结构 | 忽略同一学科内部不同问题和认知方式 | 从大问题、概念与知识动作重新定位 |
| 为了页面而过早设计模块 | 视觉结构取代知识结构 | 先交付 Markdown 底稿，确认后再转页面 |
| 追求一次读懂、一次定论 | 忽略与智者对话的递进性 | 标明当前理解、争议与下一轮阅读入口 |

## 9. AI 执行协议

当 AI 接到“为某位智者设计页面／导读”的请求时，必须遵守：

1. 先读取用户指定的原著、二手资料与现有项目文档；
2. 在未完成结构底稿前，不直接输出网页模块、视觉方案或概念卡片；
3. 不把认知方式名称当作主要结论；
4. 不将未经核实的影响关系写成师承；
5. 不把二手资料的解释写成原作者原意；
6. 对关键判断提供来源身份：原著、二手解释或后世争论；
7. 当资料不足时，明确指出缺少的是哪一层资料，而非用常识补全；
8. 先输出 Markdown 内容底稿，获得确认后再转页面。

### AI 的标准交付物

```markdown
# [智者姓名]：结构阅读内容底稿

## 资料范围与证据状态

## 核心问题

## 作者面对的对象、材料与证据

## 作者反复进行的知识动作

## 理论对话与历史位置

## 核心概念如何从问题中长出

## 文本／著作结构与阅读顺序

## 对认知方式的谨慎提炼

## 已知争议、边界与待核实事项

## 页面转换原则（非页面稿）

## 后续原著与二手资料清单
```

---

## 10. 交付前检查清单

- [ ] 我写的是作者如何形成判断，而非作者有哪些标签吗？
- [ ] 核心问题能解释为什么这些概念必须出现吗？
- [ ] 每个概念都能指出它的对手、材料、生成过程与边界吗？
- [ ] 人物关系是否真的改变了理论理解，而非只增加信息量？
- [ ] 我是否区分了原著、二手导读和后世争论？
- [ ] 我是否避免把复杂理论过快转成日常应用？
- [ ] 我是否先完成 Markdown 结构底稿，才开始页面设计？
- [ ] 页面最终是否会让读者更愿意、也更有能力回到原著？

---

## 最终原则

好的智者页面，不是替读者把智者“讲完”。

它应该让读者获得一种新的阅读能力：当再次遇到这位作者的概念、句子或著作时，知道该追问什么，知道该回到哪一条论证，知道自己此刻是在读原作者、导读者，还是后世的解释者。
